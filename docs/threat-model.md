# Threat model and controls

Phase1 deployment acceptance is complete at [the source-bound receipt](evidence/phase1-acceptance-2026-11-04.json). Phase2 is unfinished. Earlier local-only descriptions below are historical; current new-component review is recorded here and in decisions/progress.

Deployed Phase1 containment, lifecycle, budget and recovery controls have named actual evidence. Public workspace authorization and complete business verification remain unimplemented. Untrusted: public users, uploads, model output, candidate output and webhooks. Trusted but fallible: control services, configured verifier, supervisor, deployment administrator and dependency supply chain. Candidate code must not share the control host. “Independent verifier” means a permission/execution boundary from candidate code, not an unconfirmed independent human author/reviewer.

Phase2 critical review: parsers reject duplicate JSON keys, integer/Unicode/coercion ambiguity, bare CSV quotes, malformed/oversize records and normalized expansion; every source occurrence survives. Fixed diagnostics contain no uploaded cell/native exception. Lineage derives ownership from original composite keys rather than candidate identity; total-preserving swaps fail. Output decoding/empty lineage findings confer no verdict. The byte store requires trusted private directory ownership, pins/re-hashes objects and never follows arbitrary candidate paths. Separate Linux fault tests cover links, concurrent reuse, short writes and failed fsync. Review found malformed attribute declarations could expose native Unicode exceptions; fixed with bounded strict-name validation and regression cases. No new dependencies, privileges or paid resources. Remaining: bounded full-verifier/canary integration after the now-approved Q08 policy, bounded isolated verifier deployment, product auth/DB/quota/retention and crash reconciliation; no independent human sign-off or public-release clearance.

Input parser bounds encoding, headers/aliases, cells, rows, JSON depth and content; no archive extraction, pickle, XLSX or parquet. Use generated storage names outside web root. Escape code/logs/cells/filenames/model text; restrictive CSP and no raw HTML. SQL parameterization and fixed argument arrays, never user-derived shell commands. No caller fetch URLs; fixed reviewed provider/GitHub destinations and redirect restrictions. Canonical JSONL remains exact; optional human spreadsheet export is a separate formula-escaped artifact with a distinct hash/label.

Guest sessions: random high-entropy opaque token, stored hash, Secure/HttpOnly/SameSite cookies, CSRF token and Origin checks, one-hour expiry. Operator sessions <=12h with reauthentication for sensitive configuration, session rotation on login/revocation on logout. Operator roles only access assigned workspaces. Worker identity is RPC-only; verifier identity is report-only; migration role is never public request handling.

Provider/App private keys on controller service-readable secret files; short-lived installation tokens; separate mTLS, batch, session and backup keys. No secrets in NEXT_PUBLIC, source, prompts, screenshots, logs or candidate mounts. Prompt injection in source/comments/cells/stderr never widens tools or permissions. Candidate cannot edit contract, verifier, fixture oracle, CI, runtime or approval record. Development fake-provider fixtures must be labeled and impossible to enable in release.

Guest raw inputs/artifacts expire within 24h; export does not authorize indefinite server retention. Minimal metadata 7 days. Backups rolling <=24h snapshots; raw guest data may remain <=48h from upload, with actual prune/restore deletion tests. Workspace deletion immediately revokes access and queues physical deletion; tombstones prevent restore resurrection. Synthetic licensed benchmark fixtures can persist with attribution. Hashes are not automatically anonymous. Provider retention/residency remain account-specific unknowns; public intake accepts synthetic or authorized non-sensitive data only.

Incident response: pause admission/affected writes; preserve restricted evidence; revoke compromised keys; isolate affected host; rebuild trusted images; restore and reconcile hashes/outbox; retest original fault/containment; document impact before resuming. Never manually set VERIFIED/COMPLETED to clear an alert. Wrong acceptance triggers digest/version revocation and holds future outputs, followed by verifier repair and re-evaluation.

Residual risks: malicious administrator/control-host compromise, unknown kernel/runtime/dependency vulnerabilities, side channels, incomplete business contract, provider drift, single-host outages and unconfirmed human review. Tested controls must be named with their actual evidence. No universal isolation, tamper-proof audit, zero risk, formal proof or compliance claims.

## Phase 1 budget review

New protected infrastructure SQL limits application admission, not provider billing. Account-row locks plus READ COMMITTED prevent stale sum admission; successful synchronous commit must precede external I/O. Unknown dispatch/response remains held; exact replay cannot claim twice. Dispatcher cannot edit tables/caps, settle costs or assume the nonlogin owner role. Reconciler evidence remains trusted and must come from authoritative billing. Runtime must use one configured project account, never user-controlled account/category/rate inputs. A compromised administrator/dispatcher can bypass protocol; no claim of database enforcement over arbitrary network calls. Local tests exercised concurrency, crash/restart and role failures. No independent human review; critical test-image findings and missing deployment/dispatcher integration remain explicit in readiness.

Inference boundary implementation: PostgreSQL transactions acknowledge commit before dispatch; uncertain failures hold funds. Fixed HTTPS client disables redirects/environment proxy configuration and automatic retries, limits total time/raw response bytes, and validates strict JSON/model/finish status without executing it. No provider error body or DSN enters diagnostics. This remains an internal component: billing gates, secret loading, deployed database/TLS and durable orchestration composition are not implemented by its tests. See inference.md and phase1-readiness.md for evidence and review.

Worker supervisor implementation: the private durable journal authorizes only fixed server-generated execution resources. Direct runsc under a non-delegated systemd cgroup keeps runtime descendants under the independent watchdog. Startup release requires actual unit policy readback; removed staging denies delayed start. Kernel cgroup emptiness precedes collection; failed cleanup quarantines admission. Two active slots and twenty reserved result slots bound trusted staging/capture, with exact-identity replay/cancel/fencing. Real host fixtures exercise these lifecycle controls, including supervisor SIGKILL; they do not prove runsc containment, guest limits or network denial. Rootfs provenance, immutable supervisor install, authenticated mTLS service/transfer and deployed service restart remain gates. Resident capture maintenance runs after recovery and blocks admission on faults. Administrator compromise is outside this boundary. See sandbox.md for privilege review and remaining independent-human-review gap.

Service/import follow-up: authenticated TLS and immutable rootfs provenance now have local implementation/tests. Required CA/leaf pins precede parsing; fixed frame/depth/field/connection/deadline limits contain protocol work, and no operation selects host resources. Creates and captures bind expected runtime identity; durable capture/ACK reconciliation cannot manufacture verification. Docker import is explicit local/no-pull/create/export/remove, never start; archive names are not extracted onto the host. Deployment independently pins the read-only blob and verifies loop backing. New privileged trust includes the small root worker service and trusted host builder; root compromise, stolen certificates, host/kernel/parser advisories and deployed isolation remain risks. Actual service deployment/restart, public workspace authorization and all guest containment probes remain gates. No independent human review or vulnerability clearance is claimed.

Receipt/runtime update: host secret loading and durable probe evidence now exist locally. Exact-byte recovery cannot resend, settle or create a verification verdict. Function-only immutable SQL protects normal dispatcher operations; account configuration/admin remain trusted. Stale restored ledgers require external billing reconciliation. Runtime identity includes all selected companions and protected manifest, with fixed search path and root-owned file/hash validation. Kernel limit readback and sampled counters are host evidence, not guest containment proof. No independent human sign-off.


Phase2 identity/registry critical pass: fixed search paths, qualified objects, private internal authorization function, nonlogin ownership and narrow execution grants prevent table/provisioning access from the API role. Fresh workspace/session checks serialize with revocation and scoped quotas. Review moved default database/public-schema privilege revocation from fixture-only setup into the migration. Browser token helpers reject duplicate authorization headers/cookies and forged Origin; no real browser route exists yet. Local SQL tests use isolated test-only trust authentication, not production SCRAM evidence. Raw token hashing/CSRF extraction alone grants no workspace access. Still required: protected production login provisioning, immediate bounded client transactions, upload/rate/retention limits, actual HTTP cross-workspace tests and deployment review. Expiry is checked on operation authorization; no exact-instant interruption of an already authorized transaction is claimed.


Semantic-component critical pass after Q08 approval: raw duplicate equality uses all six source strings; exact groups cannot mask invalid lookup/attribute records; filters never outrank blocking violations. Candidate source identity cannot determine its own lookup owner, and candidate totals never define expected rollups. Fixed output schema blocks coercion; full occurrence accounting rejects drop/duplicate/foreign IDs and all-rejected shortcuts. Review added exact raw hashes for bounded malformed output and exact boolean/integer receipt eligibility in the deployed probe driver; reran actual worker probes after the latter change. Schema/example were recorded before reference implementation; no contract/limit was weakened to accept a candidate. Remaining: resource-bounded deployed verifier, protected canaries, authenticated durable product orchestration and no independent human sign-off.
