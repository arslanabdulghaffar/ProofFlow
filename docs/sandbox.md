# Sandbox design and compatibility gate

Deployed runtime remains DESIGN / NOT RUN. The internal supervisor, watchdog, collector and cleanup now have local tests with trusted fixtures, described below; these do not execute candidates or prove gVisor containment. Use a dedicated Vultr Linux worker, never the control VM or this Windows/WSL development computer for candidate execution. Pin build tooling, runsc binary digest/version, OS, candidate image digest and `--platform=systrap` runtime arguments. Docker builds images; the execution supervisor invokes runsc directly under systemd so runtime descendants stay in its execution cgroup. gVisor's platform guide recommends systrap for VM environments; that is not evidence that a selected Vultr plan works. See [external evidence](external-evidence.md).

The supervisor accepts only private mTLS create/status/cancel/fence operations with execution/job IDs, generation, server-approved image/limit profile, immutable manifest and hard deadline. No public Docker socket, arbitrary path, shell command, privilege or runtime flags. Non-root candidate UID, all capabilities dropped, no-new-privileges, read-only root, no host PID/IPC/network namespace/devices. Dependencies are installed in trusted image builds only. Fail readiness if explicit runsc identity/configuration is missing. Guest `dmesg` text alone is forgeable and is not runtime identity evidence.

## Controls and independent probes

| Resource | Planned enforcement | Phase 1 evidence required |
| --- | --- | --- |
| CPU | cgroup v2 quota equivalent to 1 vCPU, covering all execution processes plus runtime children; supervisor outside guest budget | Saturating workload; host cgroup counters/quota and measured throttling; application remains responsive |
| Memory | 768 MiB sandbox memory limit, bounded runtime overhead, swap disabled for the execution; reserve host headroom | Capped allocation hits configured limit, host peak/accounting and termination receipt, no host OOM |
| Guest processes/tasks | Hard and soft guest RLIMIT_NPROC=64 for unprivileged UID via immutable launcher/OCI settings, if the pinned runsc actually enforces it; host pids limit separately bounds runtime overhead | Bounded fork AND thread probes count guest tasks, deny creation above cap, prevent raising hard limit; verify pandas thread configuration. Docker host PID counts are not proof of guest count |
| Output capacity | Supervisor-owned dedicated tmpfs or equivalent per-execution filesystem, 64 MiB, restrictive ownership/mount flags | Output flood gets ENOSPC/cap violation without filling host; accounting before/after |
| Scratch capacity | Separate 64 MiB bounded mount, including /tmp and reviewed writable /dev/shm; no other writable image layer | Scratch/shared-memory flood capped; inspect all writable mounts |
| Inodes/files | Proposed `nr_inodes=1024` per bounded filesystem plus fixed output allowlist | Many zero-byte files exhaust the execution quota; no unbounded host inode growth |
| Network | runsc networking disabled/none with isolated loopback only; host egress policy defense in depth | IPv4/IPv6, DNS, metadata, control/worker private IP and controlled external endpoint probes denied |
| Wall time | Supervisor monotonic 20s timer plus independent systemd RuntimeMaxSec=20s, KillMode=control-group/SIGKILL; includes runtime descendants | Loop/background child stopped even after supervisor death, no residual guest/runtime writer, cleanup receipt |
| Collector | <=10 MiB combined allowed JSONL, <=20,000 lines; 100 KiB combined stdout/stderr with truncation flag | Large files/logs, wrong types, links, FIFO/device and filename substitutions fail safely |
| Trusted parser/verifier | Separate process/image: 1 vCPU, 512 MiB, 5s per task | Malformed/oversized/deep JSON/CSV fails within cap; no imports or execution of candidate |

Guest process control is a specific **unproven compatibility gate**. gVisor maps guest tasks differently from host processes. Inspect the pinned implementation and probe guest RLIMIT behavior; if no reliable 64-task bound can be demonstrated, do not expose uploaded code. Evaluate a reviewed runtime/throwaway-VM alternative with equivalent controls or stop. Do not substitute a host `--pids-limit=64` claim or a prompt instruction. Record runsc overhead separately so host PID/memory limits do not unexpectedly kill the supervisor.

## Stop writers without losing output

The supervisor mounts its own private bounded output/scratch filesystems and owns their lifecycle; it does not use ephemeral container-only output that vanishes on stop. It stages validated code/input bytes under fixed read-only paths and retains open parent-directory handles.

On normal exit, timeout, cancel or lost controller: terminate the entire guest including descendants; wait for runtime termination and confirm no remaining guest/runtime writers through host process/cgroup and runtime state. Freeze/stop alone without this evidence is not safe collection. Keep supervisor-owned output storage mounted after runtime termination. Mark collection uncertain if any writer cannot be ruled out; never verify racing bytes.

After termination, collect only ledger.jsonl, unresolved.jsonl and rollups.jsonl when the v1.1 contract explicitly enables it. Use directory-relative non-following opens; inspect regular-file type, link count, device/inode identity, size and bounds; forbid symlinks/hard-link anomalies, FIFOs, sockets, devices, directories and extra output entries. Read bounded bytes once, hash them, transport to immutable control storage; check identity again. Diagnostics are untrusted escaped text. Candidate receipts/reports are ignored as authority.

Copy bounded collected bytes into private durable result storage, then remove runtime resources, normally unmount job filesystems and remove only the supervisor-created execution directory. Only the private copy waits for exact controller acknowledgement or the five-minute retention sweep. Journal cleanup success/failure and sweep stale server-labeled execution IDs. Never let caller paths determine deletion. Failed cleanup disables admission until reconciled; a verified data result cannot hide a leaked execution. The hard watchdog always wins over collection convenience.

## Loop/admission limits

Original plus <=3 proposals; <=4 canary executions (one per otherwise passing original/candidate); <=5 model requests including retries; 300s total. Two execution slots, global queue <=20, guest one active job, three starts/day, one start/minute; ten starts/IP/day, 100 public starts/day, guest creation one/IP/10min. Daily counters use documented UTC windows; UI displays reset in explicit timezone. Benchmark mode can bypass guest/IP quotas only, never resource/time/cost caps. Optional witness reducer is deferred; if added, <=8 reruns/30s within the same job budget.

## Phase 1 local collector and log implementation — Nov 4

`worker/collector.py` accepts only a trusted retained directory descriptor and a strict boolean derived from the approved rollup contract. There is no public route, caller path or database verdict. The internal supervisor below proves its execution cgroup empty before calling `collect_stopped_outputs`; the function intentionally has no caller-supplied `writers_stopped=true` approval switch.

The collector opens a separate directory description, bounds enumeration to the two/three fixed names, and pins each inode using Linux O_PATH/O_NOFOLLOW before any data I/O. It checks regular type, one link and matching device, then opens that pinned inode through its trusted numeric `/proc/self/fd` reference. This avoids opening a substituted FIFO/device for I/O. It requires trusted procfs and the supervisor-owned local bounded filesystem; no attacker-supplied proc path is accepted. See [Python descriptor APIs](https://docs.python.org/3.12/library/os.html) and [Linux open semantics](https://man7.org/linux/man-pages/man2/open.2.html). These prerequisites must be checked on the eventual worker.

Combined reads stop above 10 MiB or 20,000 LF-delimited lines (a nonempty final unterminated segment counts as one line). Empty required files are retained. Bytes are read once and SHA-256 hashed; all pinned/open/path identities, sizes, mtime/ctime and directory contents are rechecked after all reads. Any failure returns no collection result and closes owned descriptors; the caller retains its original directory handle. Metadata comparisons detect the tested races, not every possible concurrent rewrite; they do not replace termination evidence. JSON/UTF-8/schema validation and immutable persistence remain separate later stages. No malformed bytes or candidate PASS text become a verdict.

`worker/log_capture.py` retains at most 100 KiB combined raw stdout/stderr in arrival order, with separate received-byte counts and truncation flags. It is a single-owner buffer only. The internal supervisor below continuously drains both streams in bounded chunks under the independent watchdog; this buffer does not implement that lifecycle or cap guest output production. Diagnostics remain untrusted bytes and must be escaped at display time.

Observed local evidence: 24 Linux stdlib tests with static synthetic files and labeled fault injection passed under WSL Ubuntu24.04/Python3.12.3. They cover exact hashes/empty files, required/forbidden rollups, extra names, symlinks/hard links/directories/FIFOs/sockets/device inodes, aggregate byte/line edges, sparse oversize rejection, retained directory identity, replacement/late/same-size writes, I/O failures and descriptor leak checks. No adversarial/candidate program was run; the device case pins existing `/dev/null` metadata with O_PATH, without device I/O or creation. Eight log-buffer tests passed on Windows; total Windows suite 30 passed with 24 Linux cases skipped there and separately executed on Linux.

Reproduce from repo root: `python3 -m unittest discover -s tests/security -v` on Linux; `uv run --locked pytest -q` and `uv run --locked ruff check api worker tests scripts/check_control_image.py` for trusted checks. No new dependency, privilege, runtime image or billable service. Worker modules are deliberately absent from the control health image. Deployed T07/T08/T15, writer termination, capture under guest flood, watchdog, persistence and resource cleanup remain NOT RUN; Phase 1 is not accepted.

Separate Codex critical review (not independent human sign-off): checked device-open races, directory replacement, final checks across all files, aggregate caps, partial-result exclusion, descriptor ownership and raw diagnostic disclosure. O_PATH pins before regular-file checks; data open uses only its own still-open descriptor. No JSON approval or cleanup state is manufactured. The internal supervisor below establishes these prerequisites for trusted local fixtures. Missing deployed integration keeps readiness 503 and public admission absent.

## Internal supervisor, watchdog and cleanup — Nov 4

`worker/supervisor.py` composes a private SQLite WAL/FULL journal, fixed staging, systemd/runsc launch, kernel writer checks, bounded collection and cleanup. Only validated UUIDs produce host paths/unit names. The immutable request binds job/generation and every input hash; replay also binds runtime/image/host and trusted supervisor source identity. Admission commits before staging, allows two unfinished executions, fences old generations and never reruns an existing execution ID. Cancellation is durable and rechecked atomically at final receipt commit. A single-process file lock and serialized admission protect capacity; cleanup uncertainty quarantines all new execution admission. Startup recovery reconciles unfinished IDs before new work.

The runtime is explicitly pinned runsc/systrap with `--network=none --ignore-cgroups=true --allow-flag-override=false`. It runs inside a root-owned systemd transient service with no delegation. This replaces Docker-daemon execution: an independent daemon could put runtime children outside the watchdog's cgroup. The fixed OCI configuration has UID/GID10001, no capabilities, no-new-privileges, read-only root/input, fixed launcher/environment, new PID/network/IPC/UTS/mount namespaces, and guest hard/soft limits. Host limits are 1 CPU, 768 MiB, zero swap and 128 host tasks; the separate 64 guest-task limit is still unproven. Read-only extracted image provenance and a matching designated-host machine identity are required; no caller-selected runtime or local production bypass exists.

An ExecStartPre gate waits for a private root-owned readiness file. The supervisor creates it only after observing the exact watchdog/resource properties on the real unit. If cancellation or uncertain submission races a late systemd start, removed staging prevents runsc from starting. systemd independently applies RuntimeMaxSec=20s and whole-cgroup SIGKILL even after the supervisor dies. Before collection, the unit must be inactive/failed, main PID zero, and its exact cgroup absent or kernel `populated=0`. Recheck after reading; missing/contradictory evidence fails closed. Guest output cannot provide this proof.

Output is a 64 MiB/1024-inode private tmpfs. Scratch is 64 MiB minus 64 KiB, shared by `/scratch`, `/tmp` and `/dev/shm`; the remaining 64 KiB and 32 inodes bound guest `/dev`. No additional writable image layer is intended. Actual runsc mount/device compatibility and enforcement remain NOT RUN. Mounts use nodev/nosuid/noexec, fixed ownership/source tags and readback. Cleanup rejects unexpected nested mounts/entries, closes retained descriptors, uses normal unmount only, removes exact owned staging and private runtime state, and confirms absence. No lazy unmount or arbitrary recursive path deletion.

The copied result is at most 10 MiB plus 100 KiB combined raw logs. Files and metadata are fsynced; capture metadata says `BYTES_PENDING_CLEANUP_NOT_VERIFIED`. Only the durable journal records final cleanup. Twenty result slots include unfinished executions, preventing concurrent retention overflow; exact replay still works at capacity. Exact manifest acknowledgement removes a copy; `maintain()` and recovery prune copies older than five minutes, protecting unfinished IDs. After recovery the supervisor starts a one-second maintenance loop; any maintenance fault blocks new admissions until explicit recovery succeeds. The loop stops before releasing the supervisor lock. Host/process downtime still delays physical deletion until recovery, and the deployed service restart policy remains unproven. Historical receipts survive copy deletion and do not guarantee bytes remain retrievable. No receipt is a verifier verdict.

Observed locally: 124 Windows tests passed, 32 Linux-only tests skipped there; all 32 Linux collector/journal tests passed separately. Nine explicit Linux root/systemd integration groups passed using **trusted fixture writers/sleepers only**: capture/replay/exact acknowledgement, wrong-policy startup denial, delayed-start denial after staging removal, simultaneous 1 MiB log draining with a 100 KiB retained prefix, extra-file rejection, resident retention expiry/fault recovery, durable cancel killing a detached child, cleanup-failure quarantine/recovery, and supervisor SIGKILL followed by independent watchdog termination/restart cleanup. All owned processes/units/mounts/staging were removed. No runsc, worker image, pandas or candidate executed. Reproduce: `python3 -m unittest discover -s tests/security -v`; on an approved local root/systemd test host, `python3 tests/security/supervisor_linux_check.py`. The latter is explicitly excluded from ordinary pytest discovery. [Receipt](evidence/phase1-supervisor-2026-11-04.json) binds source hashes and environment.

Reviewed descriptor/mount ownership, bounded draining, exact cleanup targets, crash recovery and quarantine. No new package dependency. New host privilege is limited to the dedicated worker supervisor's systemd/mount/runtime administration; candidate gains none. Actual runsc import/provenance, immutable supervisor installation, mTLS service/authenticated transfer, deployed resident service/restart composition, runtime/resource/network probes and cloud billing gates remain open.
